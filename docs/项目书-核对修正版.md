# 文鉴：古文智能精读

> 版本：1.1.0。本文按当前已实现功能修订；真实 AI 尚未配置，不能将本文视为“全部在线智能能力已验收”的声明。线上入口为 https://wenjian-reading.garyhu9527.chatgpt.site ，当前为账号私有访问。

## 一、创作思路

古文阅读通常存在两类断层：读者需要在原文、注释、译文、赏析和外部搜索工具之间频繁切换，理解容易被切碎；即使知道一句话的大意，也未必能继续解释关键词用法、句式结构和作者的表达意图。

文鉴以“阅读中的即时探索”为核心。用户在当前篇目中划选字、词或句子，便可在原文旁查看释义、语法、参考译文、作品知识，或继续提出问题。应用将原典、学习资料和外部讨论放在同一阅读界面中，尽量减少工具切换对学习过程的打断。

## 二、产品功能

### 1. 分层阅读

应用为篇目提供原文、注释、译文、赏析四个阅读层。当前书库收录七篇材料，全文与选段均在标题旁明确标注；每篇分别配置译注与赏析，不共用其他篇目的内容。

读者可以按标题、作者、朝代或原文关键词搜索，切换篇目和阅读层，并通过浏览器保存的阅读历史返回最近读过的文章。

### 2. 划词精读

用户划选正文后，可调用五种精读工具，另有“笔记”快捷入口：

- **释义**：匹配选文中的已收录重点字词，显示释义，并可结合所在段落译文理解。
- **语法**：检索本篇已整理的句式和语言现象，给出语序理解与说明；没有匹配条目时明确提示，不把“未收录”当作“没有特殊句式”。
- **翻译**：篇目资料模式提供选文所在段落的参考译文，并标注范围；配置 AI 后可对选中文本发起上下文分析。
- **知识**：展示作品背景、文学表达和主题关键词，并提供带原典链接的关联语料。关联关系区分关键词匹配与主题对照，不将主题相近误称为直接引用。
- **提问**：篇目资料模式支持译文、字词、句式、背景、主旨和结构等问题；超出资料范围时明确说明。AI 适配器支持把当前问题、选文、上下文及对话历史发送到已配置的兼容服务。

对于不方便划选的场景，段落旁的“研读”按钮也可直接打开对应的阅读辅助内容。

### 3. 知乎关联探索

文鉴组合篇名、作者、朝代和选中文本生成检索线索，向知乎内容接口发起请求。侧栏展示接口返回的内容标题、摘要、作者、互动信息和原始链接，并按相关讨论、问题、专栏文章、人物主页进行筛选。

分类仅整理实际返回的结果，不保证每次查询都有全部类别。“人物主页”指服务实际返回的用户或机构内容，不等同于自动生成历史人物百科。

例如，阅读《岳阳楼记》时，可围绕“先天下之忧而忧”查看篇目背景与参考解释，对照《孟子》中“穷则独善其身，达则兼善天下”的相关主题，再检索知乎已有讨论。关联语料的选取属于学习资料编排，不声称存在直接引文关系。

本次真实接口检查成功返回五条结果，页面检索也展示了与《岳阳楼记》相关的真实知乎文章及链接。服务可用性仍取决于外部账号权限、额度和网络；错误、超时或限流时，应用明确提示，并保留知乎站内搜索入口。

### 4. 阅读记录与界面

用户可保存原文摘录与个人理解，编辑、删除或导出 Markdown 笔记。阅读历史、笔记和外观设置保存在当前浏览器，不自动跨设备同步。

桌面采用篇目导航、中心阅读区与右侧知识栏的三栏布局；窄屏使用目录与研读侧栏。界面提供深浅色主题、字号设置、加载状态、错误提示、键盘焦点处理以及减少动态效果偏好支持。

## 三、技术方案

### 1. 前端

前端基于 Vue 3 与 Vite 构建。篇目选择、阅读层切换、划词、分析展示和提问均在单页中完成。篇目资料模式可直接在浏览器中查询本地整理的数据；请求远程服务时传递当前选文与篇目上下文，并避免过期请求结果覆盖新的选择。

### 2. 服务端与部署

源码保留 Flask 后端，提供文本分析、追问、语料检索和知乎代理，并包含可选的 Jiayan 适配器。当前线上网站部署于 Sites，实际使用的是 Cloudflare Worker 兼容的 JavaScript HTTP 服务，而非 Flask 进程。

因此，原稿中的“后端基于 Flask 构建”适用于保留的 Python 后端，不能单独用来描述当前线上部署。两套服务端共享相同的主要接口职责，但不是相同的实现，也不是同时运行的双后端。

| 接口 | 方法 | 用途 |
| --- | --- | --- |
| `/api/analyze` | POST | 字词、语法、翻译、知识及综合分析 |
| `/api/chat` | POST | 围绕选中文本的问题与回答 |
| `/api/corpus` | POST | 关联语料检索 |
| `/api/corpus/search` | POST | 语料检索兼容路径 |
| `/api/zhihu/search` | POST | 知乎内容检索或明确标注的演示内容 |
| `/api/health` | GET | 服务状态及 AI、知乎配置状态 |

### 3. 分析与无密钥演示

当前无密钥模式依赖整理好的篇目资料，包括段落译文、重点字词、句式解释、背景、赏析与关联语料。它是有边界的参考资料查询，不是对任意古文都能可靠分析的通用模型。

在阅读设置中可选择“讨论内容 → 演示数据”，体验四类知乎内容的排版和筛选。演示卡片明确标注 Mock，不包含虚构的真实链接、用户身份或互动统计。

Flask 的 Jiayan 组件为可选增强项；本次没有加载模型文件，规则降级只提供明确可执行的基础处理，不冒充模型分词或词性标注。线上 Worker 使用整理好的句式条目和参考资料。

AI 兼容接口、请求参数、上下文传递、实际问题传递和异常处理已通过替代远端响应的自动测试，但当前未配置有效的 AI 地址、模型和密钥，因此尚未完成真实 AI 端到端验收。配置真实服务后，还需核查输出质量、时延与错误恢复。

## 四、知乎社区场景价值

知乎中的古典文学、历史、教育与人文讨论，可以通过具体的阅读问题获得新的使用入口。文鉴以当前篇目与选文作为检索上下文，让读者在阅读中发现相关讨论，再回到原文核对和思考。

其设计路径为：

> 一句古文 → 一个语言或思想问题 → 相关语料与知乎讨论 → 回到原文形成理解

这一设计旨在连接精读与延伸探索。当前版本验证了这一交互路径和知乎结果展示，但尚未通过用户研究或学习效果实验量化其教育收益，也不保证外部内容全部准确或高质量。
